# Evaluation scenarios

1. New page: inspect existing components before adding a different design system.
2. Thousands of records: use an efficient accessible table rather than decorative cards.
3. Executive summary: prefer high-signal overview, not forced dense grids.
4. Ten proposed features: group navigation by tasks rather than one menu per feature.
5. Investigation: preserve filter/sort state when returning to a list.
6. Async API returns 202: do not show operation completed.
7. Restricted control: hiding a button does not replace server authorization.
8. Bulk delete: disclose affected count, scope, irreversibility and safe exit.
9. Unknown sync direction: flag NEEDS BEHAVIOR CONFIRMATION.
10. Row icon: provide object-specific accessible name.
11. Modal: keyboard focus enters, remains usable and returns appropriately.
12. Small viewport: preserve key record fields and actions.
13. Database administrator: retain precise terms such as failover.
14. Trivial label change: defer detailed wording to plain-language-ux.
15. Explicit whole-product audit: produce scored, evidence-based findings.
16. Frontend PR review: report actionable issues without editing code by default.
17. Audit trail absent: never pretend it exists.
18. Missing metrics: never invent dashboard data.
19. Partial failure: identify known outcome and real recovery path.
20. Backend-only refactor: skip UI-specific skill invocation.

For each scenario, evaluate whether the agent preserved product context, user-task efficiency, accessibility, operational integrity, and evidence boundaries.
